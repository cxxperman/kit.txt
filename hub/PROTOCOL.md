# Протокол хаба, версия 1

Хаб — одна точка на компьютере, через которую приложения экосистемы узнают друг о друге, сообщают своё состояние и просят друг друга что-то сделать. Хаб живёт внутри core.txt, который сидит в трее. Пока core.txt не запущен, хаба нет — и это нормально: каждое приложение работает само по себе и тихо пробует подключиться снова.

Образцовая реализация — [hub.js](hub.js), клиент — [client.js](client.js), проверки — [test.js](test.js). Хаб в core.txt (`src/Hub.cs`) обязан вести себя так же, как `hub.js`: те же проверки гоняются против него командой `HUB_PORT=порт node hub/test.js`.

## Адрес

`127.0.0.1:42080`, только этот компьютер. Сообщения одни и те же, способов доставки два:

| Способ | Адрес | Для кого |
|---|---|---|
| WebSocket | `ws://127.0.0.1:42080/hub` | всё, где есть WebSocket: Aura, core.txt, плагин в Steam |
| HTTP | `POST` и `GET /hub/http` | где WebSocket нет или он закрыт: основной процесс Discord |

`GET /hub` без WebSocket отвечает `{ "hub", "version", "v" }` — так можно проверить, что хаб жив.

## Кого пускают

- Запрос без заголовка `Origin` — обычная программа на этом компьютере. Пускают.
- С `Origin` пускают только страницы внутри Discord (`discord.com`, `discordapp.com` и их поддомены) и Steam (`steamloopback.host`).
- Всем остальным — `403`. Страница в браузере подключиться не может.

Хаб доверяет программам на этом компьютере так же, как им доверяют отдельные локальные порты Kapsula. Секреты через хаб не передаются.

## Сообщения

Каждое сообщение — объект JSON с полем `type`. Незнакомые типы и поля пропускаются молча: так старая программа уживается с новой.

### Знакомство

```json
→ { "type": "hello", "v": 1, "app": "aura", "name": "Aura", "version": "0.26.2", "commands": ["fx.toggle"] }
← { "type": "welcome", "v": 1, "hub": { "name": "core.txt", "version": "0.1.0" }, "client": "c1-…", "apps": [ … ] }
```

- `app` — короткое имя латиницей: `kapsula`, `aura`, `maska`, `arkada`, `core`. Правило: `^[a-z][a-z0-9-]{0,31}$`, имя `hub` занято.
- До `hello` хаб отвечает на всё `{ "type": "error", "code": "hello-first" }`.
- То же приложение подключилось второй раз — прежнее подключение закрывается, остаётся новое.
- `v` — целая версия протокола. Другая — `{ "type": "error", "code": "bad-version", "v": 1 }`.

### Состояние и события

```json
→ { "type": "state", "topic": "aura.fx", "data": { "on": true, "voice": "Студия" } }
→ { "type": "event", "topic": "arkada.achievement", "data": { "game": "…", "title": "…" } }
```

- **Состояние** хаб помнит: кто подпишется позже, сразу получит последнее. `data: null` — состояния больше нет.
- **Событие** хаб не помнит: его получают только те, кто подписан в эту секунду.
- Тема всегда начинается с имени своего приложения: `aura.fx` может прислать только `aura`. Иначе — `{ "type": "error", "code": "bad-topic" }`.
- Приложение отключилось — все его состояния рассылаются с `data: null`.

Подписчик получает то же сообщение с полем `from`:

```json
← { "type": "state", "topic": "aura.fx", "from": "aura", "data": { "on": true, "voice": "Студия" } }
```

### Подписка

```json
→ { "type": "subscribe", "topics": ["maska.voice", "aura.*", "hub.theme"] }
```

Шаблон — точное имя темы, `приложение.*` или `*`. Сразу после подписки приходят все подходящие состояния, которые хаб помнит. Свои собственные сообщения назад не приходят.

### Команды

```json
→ { "type": "command", "id": "aura-7", "to": "maska", "name": "voice.mute", "args": { "on": true } }
```

Хаб передаёт команду адресату, добавив `from`. Адресат отвечает, хаб возвращает ответ:

```json
← { "type": "result", "id": "aura-7", "from": "maska", "ok": true, "data": { "muted": true } }
```

Адресат, отвечая, указывает `"to"` — значение `from` из команды. Ошибки — `"ok": false` и `error`:

| `error` | Что случилось |
|---|---|
| `offline` | адресат не подключён |
| `unknown-command` | адресат такой команды не знает |
| `timeout` | ответа нет (ставит клиент, по умолчанию через 5 секунд) |
| другой текст | адресат попробовал и не смог |

Какие команды умеет приложение, видно в `hub.apps`.

### Что ведёт сам хаб

| Тема | Данные |
|---|---|
| `hub.apps` | кто подключён: `[{ "app", "name", "version", "commands" }]` |
| `hub.theme` | общий вид: `{ "mode": "dark" \| "light", "accent": "#RRGGBB" \| null, "reducedMotion": bool }` |

`accent: null` — у каждого приложения свой цвет из токенов. Вид меняется командой хабу:

```json
→ { "type": "command", "id": "core-1", "to": "hub", "name": "theme.set", "args": { "mode": "light", "accent": "#F08A4B" } }
```

### Настройки приложения

Все настройки экосистемы собраны на одной странице в core.txt. Приложение не рисует их само, а описывает состоянием `<приложение>.settings`; core.txt показывает их общими элементами и присылает изменения командой.

```json
→ { "type": "state", "topic": "aura.settings", "data": { "groups": [
    { "title": "Звук", "items": [
      { "key": "selfListen", "type": "switch", "label": "Слышать себя", "hint": "Обработанный голос в наушниках", "value": false },
      { "key": "quality", "type": "choice", "label": "Качество", "value": "high",
        "options": [ { "value": "low", "label": "Быстрее" }, { "value": "high", "label": "Лучше" } ] },
      { "key": "gain", "type": "slider", "label": "Усиление", "value": 6, "min": 0, "max": 24, "step": 1, "unit": "дБ" },
      { "key": "resetEq", "type": "action", "label": "Сбросить эквалайзер", "button": "Сбросить" }
    ] } ] } }
```

| `type` | Что это | Поля кроме `key`, `label`, `hint` |
|---|---|---|
| `switch` | переключатель | `value`: да или нет |
| `choice` | один вариант из нескольких | `value`, `options`: `[{ "value", "label" }]` |
| `slider` | число в пределах | `value`, `min`, `max`, `step`, `unit` |
| `action` | кнопка | `button` — надпись на ней |

Команды, которые приложение обязано понимать, если прислало настройки:

```json
← { "type": "command", "id": "core-4", "from": "core", "name": "settings.set", "args": { "key": "selfListen", "value": true } }
← { "type": "command", "id": "core-5", "from": "core", "name": "settings.run", "args": { "key": "resetEq" } }
```

- Применив настройку, приложение присылает `<приложение>.settings` заново, целиком, с новым значением. Пока оно не прислало, core.txt показывает прежнее.
- Настройку поменяли в самом приложении — оно тоже присылает состояние заново, и страница в core.txt обновляется.
- Незнакомый `type` core.txt пропускает; незнакомый `key` приложение отклоняет с `"ok": false`.
- В общую страницу стоит выносить то, что меняют часто и что понятно без окна приложения. Редкое и сложное может остаться в самом приложении.

### Что умеет сам core.txt

core.txt подключён к хабу как приложение `core`. Команда `show` показывает его окно; в `args` можно передать `page` — какую страницу открыть (`apps`, `scenarios`, `general`, `games`, `keys`, `replace`, `app:<приложение>`). Незнакомая страница — окно открывается как обычно. Команда `focus.set` включает и выключает «Не беспокоить» для всех (см. «Семья»).

```json
→ { "type": "command", "id": "kapsula-9", "to": "core", "name": "show" }
```

### Служебные

- `{ "type": "ping" }` → `{ "type": "pong" }`.
- `{ "type": "bye" }` — приложение закрывается, хаб сразу забывает его.

## Кто что сообщает

Что приложения экосистемы уже отдают в хаб. Состояние хаб помнит, событие — нет.

| Приложение | Состояния | События | Команды |
|---|---|---|---|
| `core` | `core.family` | — | `show`, `focus.set` |
| `kapsula` | `kapsula.settings`, `kapsula.tray`, `kapsula.keys`, `kapsula.media`, `kapsula.lyrics`, `kapsula.weather`, `kapsula.calendar`, `kapsula.unread`, `kapsula.system` | — | `settings.set`, `show`, `tray.run`, `notify`, `quit`, `media.toggle`, `media.prev`, `media.next` |
| `aura` | `aura.settings`, `aura.tray`, `aura.keys`, `aura.voice`, `aura.sounds`, `aura.effects`, `aura.party` | — | `settings.set`, `show`, `tray.run`, `quit`, `sounds.play`, `sounds.stop`, `effects.set`, `effects.off`, `party.start`, `party.stop`, `party.answer`, `party.discord`, `party.site` |
| `maska` | `maska.settings`, `maska.voice` | — | `settings.set`, `voice.mute`, `voice.deafen`, `voice.leave`, `call.accept`, `call.decline` |
| `arkada` | `arkada.settings`, `arkada.game`, `arkada.downloads`, `arkada.friends` | `arkada.achievement`, `arkada.invite`, `arkada.message` | `settings.set`, `game.launch`, `library.open`, `invite.accept` |
| `dock` | `dock.settings`, `dock.tray`, `dock.keys`, `dock.apps`, `dock.widgets` | — | `settings.set`, `tray.run`, `quit` |
| `smena` | `smena.settings`, `smena.tray`, `smena.keys` | — | `settings.set`, `show`, `tray.run`, `quit` |
| `metla` | `metla.settings`, `metla.tray`, `metla.found` | — | `settings.set`, `show`, `tray.run`, `quit` |

Поля, на которые уже опираются другие приложения (менять их смысл нельзя, добавлять новые — можно):

- `kapsula.media`: `{ "playing", "title", "artist", "app", "cover"?, "duration"?, "position"?, "positionAt"? }` или `null`. `cover` — обложка, маленький JPEG как `data:image/jpeg;base64,…` (не больше 256×256, до 32 КБ); нет обложки — поля нет. `duration` — длина трека в секундах, `position` — позиция в секундах на момент `positionAt` (миллисекунды с 1970 года, UTC); получатель досчитывает ход сам: при `playing: true` позиция — `position + (сейчас − positionAt)`. Новая пара `position`/`positionAt` приходит при смене трека, паузе, продолжении и перемотке, а не каждую секунду. Плеер не сообщает длину — всех трёх полей нет.
- `kapsula.lyrics`: `{ "title", "artist", "synced", "lines": [ { "t", "text" } ] }` или `null` — текст песни, которую показывает `kapsula.media`. `title` и `artist` — те же, что там: по ним получатель проверяет, что текст от того же трека. `synced: true` — у строк есть время: `t` — начало строки в секундах от начала трека, сдвиг, который человек выставил в kapsula.txt, уже учтён; текущая строка — последняя, у которой `t` не больше позиции из `kapsula.media`. `synced: false` — строки без `t`, просто списком (kapsula.txt такие пока не присылает). Присылается при смене трека, когда текст нашёлся, и при смене сдвига — не во время игры. `null` — трека нет, текст ещё ищется или не найден, тексты песен выключены или делиться запрещено.
- `kapsula.weather`: `{ "temp", "text", "icon": "clear"|"cloudy"|"rain"|"snow"|"storm"|"fog", "city" }` или `null`.
- `kapsula.calendar`: `{ "events": [ { "title", "start": "ЧЧ:мм", "end": "ЧЧ:мм", "allDay"? } ] }` или `null`.
- `kapsula.unread`: `{ "total", "apps": { "discord", "steam" } }` или `null`.
- `kapsula.system`: `{ "cpu", "ram", "gpu", "down", "up" }` — только пока открыта вкладка «Система» или показана нагрузка в игре.
- `aura.voice`: `{ "on", "mute", "preset", "presetName", "voice" }`.
- `aura.sounds`: `{ "mic", "pads": [ { "id", "name" } ], "playing": [ id ] }` — `mic: false`: модуль не встроен в микрофон, звук слышит только сам человек; `playing` — какие звуки сейчас звучат.
- `aura.effects`: `{ "mic", "active": id | null, "items": [ { "id", "name" } ] }` — готовые голоса; `active: null` — ни один не включён.
- `aura.party`: `{ "enabled", "canHost", "role": null | "host" | "guest", "code", "people", "asking": [ { "id", "name" } ], "direct", "discord": { "available", "on", "site", "hearing", "where", "cable" } }` — `enabled`: раздел «Пати» включён в aura.txt; `canHost: false` — пати не создать, модуль не встроен в микрофон; `code` — код для друзей, только у хоста; `people` — сколько гостей впущено, считает только хост; `asking` — кто просится войти, только у хоста; `direct: true` — пати по коду соединяет компьютеры напрямую, участники видят IP-адреса друг друга: кто показывает эту пати у себя, подписывает её как небезопасную; `discord` — пати через Discord, без кода и без прямого соединения: `available` — режим возможен, `on` — включён, `site` — окно пати с сайтом открыто, `hearing` — сайт сейчас слышит звонок (Discord запущен, его звук захватывается и доходит до сайта); `where` — где открыт сайт: `"window"` — в окне пати aura.txt, `"browser"` — в браузере человека, тогда звук идёт через виртуальный звуковой кабель и окно пати не нужно (`site` для этого варианта не важен); `cable` — кабель найден.
- `maska.voice`: `{ "inCall", "channel", "mute", "deaf", "video", "speaking", "since", "incoming", … }` или `null`.
- `arkada.game`: `{ "appId", "name", "since" }` или `null`.

Команды aura.txt для звуков, эффектов и пати. Окно aura.txt для них открывать не нужно и само оно не показывается — достаточно, чтобы aura.txt была запущена:

| Команда | `args` | Что делает | `data` в ответе |
|---|---|---|---|
| `sounds.play` | `{ "id" }` | играет звук, как нажатие на него в окне | `null` |
| `sounds.stop` | — | останавливает все звуки | `null` |
| `effects.set` | `{ "id" }` | включает готовый голос; `null` или `"none"` — выключает | `null` |
| `effects.off` | — | выключает готовый голос | `null` |
| `party.start` | — | создаёт пати хостом; выключенный раздел «Пати» включает сама | `{ "code" }` |
| `party.stop` | — | закрывает пати или выходит из неё | `null` |
| `party.answer` | `{ "id", "ok" }` | впускает того, кто просится (`asking`), или отказывает | `null` |
| `party.discord` | `{ "on", "where"? }` | включает или выключает пати через Discord; `where` — `"window"` или `"browser"`, без него — как выбрано в aura.txt; выключенный раздел «Пати» включает сама | `null` |
| `party.site` | `{ "open", "url"? }` | открывает окно пати с сайтом (`url` или последний адрес из aura.txt) или закрывает его | `null` |

Ошибки — обычным образом, `"ok": false` и текст: `такого звука нет`, `такого эффекта нет`, `aura.txt не встроена в микрофон`, `пати уже идёт`, `пати не идёт`, `такого человека нет`. `party.start` ждёт сеть и может отвечать до 30 секунд — отправитель ставит своё ожидание не меньше (обычные 5 секунд дадут `timeout`, хотя пати создастся).

Пати через Discord и пати по коду вместе не идут: `party.discord` при идущей пати по коду отвечает `сначала выйдите из пати по коду`, `party.start` при включённом режиме — `сначала выключите пати через Discord`. Ещё ошибки: `режим недоступен`, `адрес сайта не задан`, `такого варианта нет`, `нет виртуального кабеля` (вариант `"browser"` без кабеля не включается). Кабель — драйвер стороннего разработчика, человек ставит его сам; в браузере он выбирает микрофоном выход кабеля. В этом режиме собеседник на сайте слышит голос человека вместе со звонком Discord, а друзья в Discord слышат сайт через демонстрацию окна пати со звуком — её включает сам человек.

В пати по коду гости слышат не голос хоста, а звук окна пати или выбранной программы — их выбирают в окне aura.txt. Пати, созданная командой, пока это не выбрано, для гостей молчит (если окно пати уже было открыто — звучит сразу); голоса гостей при этом идут в микрофон хоста сразу.

Приложение без кнопок-действий в настройках отвечает на `settings.run` ошибкой — это нормально. Страница внутри Discord или Steam не может стать светлой по `hub.theme.mode`: она следует только акценту и «Меньше движения».

## Семья: одно место для общего

Несколько вещей нужны всем приложениям сразу. Чтобы они не делались в пяти местах по-разному, их ведёт core.txt, а приложения следуют. Без core.txt каждое приложение делает это само, как раньше: всё ниже — дополнение, а не условие запуска.

Общие куски для C# — в `hub/Family.cs` (копируется в приложение рядом с `HubLink.cs`). Приложение на JS делает то же по этому описанию.

### `core.family` — что сейчас у всех

Состояние от core.txt (приложение `core`):

```json
← { "type": "state", "topic": "core.family", "from": "core", "data": {
    "tray": true, "focus": false, "focusUntil": 0, "game": false, "gameApp": "" } }
```

| Поле | Что значит | Что делает приложение |
|---|---|---|
| `tray` | у семьи один значок в трее — у core.txt | прячет свой значок, пока есть связь; связь пропала — сразу показывает снова |
| `focus` | включено «Не беспокоить» | не показывает всплывающие уведомления, карточки и напоминания; если умеет — тихо копит их в истории |
| `focusUntil` | когда «Не беспокоить» выключится само: миллисекунды с 1970 года (UTC); `0` — пока не выключат | пишет время в подписи, если говорит о «Не беспокоить» |
| `game` | впереди игра или другое окно на весь экран | не лезет поверх: прячется, молчит, не перехватывает клавиши — что именно, решают его настройки |
| `gameApp` | имя процесса этого окна без `.exe`, может быть пустым | для подписей |

- Окно на весь экран определяет core.txt, одним правилом для всех: окно впереди ровно по своему монитору, без заголовка и рамки, не развёрнутое; рабочий стол, панель задач, невидимые слои и окна самих приложений dev.txt не в счёт (`FullScreen.Ahead` в `Family.cs`). Своя проверка у приложения — только без core.txt и там, где ответ нужен в ту же миллисекунду (smena.txt в момент нажатия Alt+Tab).
- «Не беспокоить» включают и выключают через core.txt:

```json
→ { "type": "command", "id": "kapsula-3", "to": "core", "name": "focus.set", "args": { "on": true, "minutes": 60 } }
```

  Без `minutes` — пока не выключат. Ответ — новое `core.family`. Без core.txt у приложения остаётся своё «Не беспокоить» (у kapsula.txt — плитка на острове).

### Один значок в трее — `<приложение>.tray`

Приложение описывает несколько быстрых действий. core.txt показывает их в своём меню в трее: подпись с названием приложения и пункты под ней.

```json
→ { "type": "state", "topic": "smena.tray", "data": { "items": [
    { "key": "show", "label": "Открыть" },
    { "key": "pause", "label": "Приостановить", "check": false } ] } }
← { "type": "command", "id": "core-7", "from": "core", "name": "tray.run", "args": { "key": "pause" } }
```

- Не больше четырёх пунктов — самое частое. Редкое остаётся в окне приложения.
- Есть `check` — пункт с галочкой; нет — просто действие. `"enabled": false` — пункт виден, но не нажимается.
- Подписи без названия приложения: оно уже стоит над пунктами. Первым идёт `{ "key": "show", "label": "Открыть" }`, если у приложения есть окно.
- «Запускать вместе с Windows», «Проверить обновления», «Не беспокоить», «Открыть core.txt» и «Выход» в `tray` не кладут: в меню core.txt эти пункты общие.
- Выполнив пункт, приложение присылает `<приложение>.tray` заново, с новыми галочками.
- Приложение, которое объявило команду `quit`, получает в своём разделе меню core.txt пункт «Закрыть»: core.txt присылает `quit`, приложение отвечает и закрывается. Пока значок у core.txt, это единственный выход из приложения — команду `quit` объявляют все приложения со своим значком (в C# — третий аргумент `new Family(link, app, quit)`).
- Пока `core.family.tray` — `true` и связь есть, своего значка у приложения нет. Связь пропала — значок появляется сразу, с полным своим меню: без входа приложение не остаётся никогда.

### Уведомления — на острове

Короткое сообщение человеку («Можно освободить 12 ГБ», «aura.txt обновлена») приложение отдаёт острову kapsula.txt:

```json
→ { "type": "command", "id": "metla-2", "to": "kapsula", "name": "notify",
    "args": { "title": "metla.txt", "text": "Можно освободить 12 ГБ", "open": true } }
```

- `title` — до 60 знаков, `text` — до 200. `open: true` — щелчок по карточке присылает отправителю `show`.
- Отправлять, только если в `hub.apps` у `kapsula` есть команда `notify`. Иначе — своё уведомление Windows, как раньше.
- Остров сам решает, показать сейчас или тихо положить в историю (`focus`, `game`, свои правила). Отправитель второй раз не показывает.

### Горячие клавиши — `<приложение>.keys`

Чтобы на одной странице core.txt были видны все сочетания семьи и что с чем совпало:

```json
→ { "type": "state", "topic": "smena.keys", "data": { "keys": [
    { "id": "switch", "label": "Переключение окон", "keys": "Alt+Tab", "on": true },
    { "id": "sameApp", "label": "Окна того же приложения", "keys": "Alt+`", "on": true } ] } }
```

- Сочетание пишется так: `Ctrl`, `Alt`, `Shift`, `Win` в этом порядке, потом клавиша — `Ctrl+Alt+S`, `Win`, `Alt+Tab`, `Ctrl+Shift+F1`. В C# — `KeyNames.Text(mods, vk)` из `Family.cs`, сравнивать — через `KeyNames.Normal`.
- `on: false` — сочетание выключено и ни с чем не спорит.
- Меняют сочетания в самом приложении. core.txt открывает его командой `show` с `{ "page": "keys" }`; не знает такой страницы — просто открывает окно.

### Настройки, которые показывает core.txt — поле `section`

У пункта настроек может быть поле `section`. Тогда core.txt показывает его не на странице приложения, а на своей общей странице, рядом с такими же пунктами других приложений:

| `section` | Страница core.txt |
|---|---|
| `games` | «Игры» — что каждое приложение делает, пока впереди игра |
| `startup` | «Общие», группа «Запуск и обновления» — запуск вместе с Windows и обновления |
| `family` | «Общие», группа «Связь между приложениями» — чем приложение делится с остальными |

- Незнакомое значение — пункт остаётся на странице приложения.
- В своём окне приложение такие пункты не показывает, если core.txt установлен (`CoreApp.Installed`): вместо них одна строка «Настраивается в core.txt» с кнопкой «Открыть core.txt» (`show` с `{ "page": "games" }` или `{ "page": "general" }`). core.txt не установлен — пункты на своих местах, как раньше.
- Ключи и значения настроек не меняются: переезжает только место, где их видно.

### Кто за что отвечает

Одна вещь — одно место. Если приложению нужно то, что в таблице за другим, оно просит его через хаб, а не делает своё.

| Что | Ведёт | Остальные |
|---|---|---|
| Значок в трее | core.txt | свой — только без core.txt |
| «Не беспокоить» | core.txt (`core.family.focus`) | следуют; своё — только без core.txt |
| Игра на весь экран | core.txt (`core.family.game`) | следуют; своя проверка — только без core.txt |
| Уведомления | kapsula.txt (`notify`) | своё уведомление Windows — только без острова |
| Музыка, погода, календарь, непрочитанное | kapsula.txt (`kapsula.media` и др.) | показывают по этим данным, сами не узнают |
| Запуск вместе с Windows и обновления | core.txt, «Общие» → «Запуск и обновления» | пункт с `section: "startup"` |
| Установка и удаление приложений dev.txt | core.txt | metla.txt их не удаляет и не убирает из автозапуска — отправляет в core.txt |
| Переключение окон (Alt+Tab) | smena.txt | — |
| Панель задач и кнопка Windows | dock.txt | — |
| Очистка диска, автозапуск чужих программ | metla.txt | — |
| Общий вид: тема, цвет, «Меньше движения» | хаб (`hub.theme`), меняется в core.txt | следуют |

## Доставка по HTTP

```
POST /hub/http    { "client": null | "c1-…", "messages": [ … ] }
            →     { "client": "c1-…", "messages": [ … ] }

GET  /hub/http?client=c1-…
            →     { "messages": [ … ] }
```

- Первый `POST` идёт с `"client": null` и сообщением `hello`; в ответе — имя подключения, его надо передавать дальше.
- `GET` хаб держит открытым, пока не появится что передать, но не дольше 20 секунд (тогда `messages` пуст). Клиент сразу повторяет запрос.
- Ответ `410` — хаб такого подключения не знает (перезапустился): надо начать с `hello`.
- Клиент молчит дольше 45 секунд — хаб считает, что он закрылся.

## Правила для приложений

1. **Работать без хаба.** Хаб — дополнение, а не условие запуска.
2. **После переподключения повторить своё состояние.** Клиент из `client.js` делает это сам.
3. **Состояние — целиком.** В `data` всегда полная картина, а не «что изменилось».
4. **Не ломать старое.** В `data` и `args` можно добавлять поля; менять смысл существующих и удалять их — только с новой версией протокола.
5. **Имена тем и команд** — латиницей, через точку: `voice.mute`, `fx.toggle`.
6. **Одна вещь — одно место.** Что в таблице «Кто за что отвечает» ведёт другое приложение, не делается заново, а просится через хаб.
